# 语音电话助手 (VoiceCallAssistant)

在 [VoiceClock](https://github.com/haoliying/VoiceClock) 的基础上扩展的语音控制版本：离线语音识别 + 离线语音合成，全部在本机完成，不联网（仅在首次启动时下载一次 TTS 模型）。

## 功能

1. **语音问时间**：说“几点了”，播报当前时间。
   识别前会做一层降噪与增益，嘈杂环境下更稳：
   - 优先挂系统自带的 NoiseSuppressor / AEC / 自动增益（国产 ROM 常常不可用，日志 `[音频] 系统降噪=…` 会写明）；
   - 不可用时走软件处理：110Hz 高通去低频轰鸣、按环境噪声底做的自适应噪声门、慢速 AGC 把说话声拉到固定电平；
   - 口令匹配加了同音字归并（“机点啦”→“几点了”、“接点话”→“接电话”），并按常见说法扩充了同义词。
2. **来电报姓名**：姓名按 **来电通知 → 通讯录号码匹配 → 通话记录 CACHED_NAME** 的顺序取，
   都没有才念号码。通讯录查询只针对这一个来电号码（`PhoneLookup`），不批量读取、不上传；
   华为这类不发可读来电通知的 ROM，只能靠通讯录这一级。
   有人名就播“张三来电话”；只有号码时按 **3-4-4 分组**念：
   “一八五，六零一八，一一四五，来电话”（组内连读、组间停顿，像正常人报号码），
   整句合成一次并按号码缓存，同一号码再次来电直接播放。合成失败时就地再合成一次，
   不再拼接单字（单字拼接会一字一顿，听起来像喘不上气）。
   每条来电通知的原文都会写进日志（`[通知] 来自 … | … | 按钮=…`），界面上也会显示
   “最近来电通知：…”，可以直接看到到底读到了什么；像来电但没被采用的通知也会记一条
   `[通知] 未采用 …`，方便判断系统到底发了什么。
   日志里会写明姓名是从哪一级读到的（`从通讯录读到姓名` / `通话记录里读到姓名` /
   `通讯录里没有这个号码`），读不到时不会悄悄退回号码。
   所有来源都做了“姓名里不许有数字”的校验：有些 ROM 的 `CACHED_NAME` 或通知里存的就是
   **带国家码的号码**，直接送进 TTS 会被读成“一万八千五百……”，现在一律改走按位念号码。
3. **响铃期间重复播报**：**系统静音 / 勿扰 / 铃声音量为 0 时不播报**（仍然听口令、能接听），
   每次播报前都重新检查一次系统音量状态。
   播报时麦克风是关着的（半双工），避免把自己的声音识别成指令；
   每轮播完留 4.5 秒干净时间给用户说话，最多念 4 遍，之后保持安静继续听，
   直到系统报告铃声停止（对方挂断/超时/接通）为止，且每轮前都会重新确认通话状态。
4. **语音接听**：响铃时说“接电话”，自动接听（播报刚结束的那几秒最容易识别）。
   优先点击来电通知上的“接听”按钮；没有该按钮时走**无障碍服务**（找“接听”按钮点按，
   点不动就按位置点按，再不行上滑手势），之后才尝试“系统接口 → 兼容接口 → 耳机键”。
   每一步都用通话状态验证是否真的接通（很多 ROM 上系统接口不报错但不生效），
   日志里会写明每一步的结果。华为这类 ROM 上，无障碍基本是唯一能接通的通道。
5. **语音挂断**：响铃或通话中说“挂断电话”，自动挂断。同样支持播报中打断。
6. **口令可配置**：三个口令都可以在界面里改，保存后立即生效，不需要重启服务。
7. **识别模型可选**：内置标准模型够用、省内存；嘈杂环境、口音重时可在界面上切到高清模型
   （1.27GB，后台下载、断点续传，下载完自动热切换，详见下文“识别模型”）。

## 首次使用

1. 安装 APK，打开应用。应用会按顺序引导授权，缺哪一步就自动跳到对应页面：
   1) **运行时权限**：录音、电话状态、接听电话（必开），通讯录（读姓名）、通话记录、拨打电话。
   2) **通知使用权**：有的话优先用通知里的姓名和接听按钮（华为通常没有，开不开都不影响接听）。
   3) **无障碍服务**：**华为/鸿蒙上这是唯一能接通的通道**，不开就接不了。
      点“去开启”会直接跳到本服务的开关页；入口在 设置 → 辅助功能 → 无障碍 →
      无障碍服务（有的版本叫“已下载的服务”）→ 语音助手来电辅助。
      华为还会把无障碍服务后台清掉：设置 → 应用和服务 → 应用启动管理 →
      语音电话助手 → 关闭“自动管理”，打开“允许自启动/允许后台活动”。
   每一步每次启动只跳一次，不会反复弹；界面上的“授予/检查权限”可以重新走一遍。
2. 点“启动服务”，首次启动会下载约 116MB 的语音合成模型并解压，之后不再下载。
3. 日志里 `[来电] 权限 …` 与 `[通知] 来自 …` 会列出实际读到的内容；
   “复制日志”会把权限状态、最近一条来电通知和完整后台日志一起复制到剪贴板。
4. 手机设置里把本应用加入电池优化白名单，避免后台被杀。

## 识别模型（标准 / 高清）

界面上的“切换识别模型”可以在两个 Vosk 中文模型之间切换：

| | 标准（内置） | 高清 |
| --- | --- | --- |
| 下载 | 无需下载，随 APK 内置 | 首次使用下载 1.27GB（`vosk-model-cn-0.22`） |
| 占用 | 约 66MB | 解压后约 2.0GB，解压期间加压缩包共需约 3.4GB |
| 内存 | 很小 | 加载后常驻内存明显更大，建议总内存 ≥ 3GB |
| 准确率 | 一般，安静环境够用 | 嘈杂环境、口音、远场说话明显更准 |

选择高清后点“应用”：

1. 服务会很快重启一次（几秒），**先照常用内置标准模型监听**，
   高清模型的下载/解压在后台线程进行：下载 1.27GB 期间来电话照样播报、照样能接；
2. 下载走服务自身（前台服务 + 唤醒锁），**支持断点续传**：网络中断、应用被杀，
   下次启动会从已下载的那部分继续（按字节 Range 请求），不会从头再来；
   服务器返回的大小和本地对不上时会自动重新下载；
3. 解压到 `vosk-model-hd.tmp` 并校验每个文件的长度，成功后才替换正式目录，
   不会出现“用了一半的模型”；
4. 解压完自动删除 1.27GB 的压缩包；
5. 下载+解压完成、且总内存 ≥ 3GB 时，识别线程会**热切换**到高清模型
   （先建新引擎再关旧引擎，失败就保留标准模型，服务不中断）；
6. 存储不足、内存不足、文件损坏时自动继续用标准模型，日志里会写明原因，
   不会让应用起不来；
7. “删除高清模型”会清掉模型目录、临时目录和压缩包；如果当时正在用高清模型，
   会自动切回标准模型并重启服务。

下载/解压进度显示在通知栏和界面的加载提示里（`正在下载高清识别模型 45%` /
`正在解压高清识别模型 62%`）。

## 界面状态

服务的运行状态由同进程的服务实例直接判断，界面每次回到前台都会重新读取，不会再出现
“服务明明在跑却显示启动服务”的错位；用 Android 的绑定方式探测会顺带把服务创建出来，已弃用。

## 已知限制

- **通话中录音**：Android 10 以后第三方应用无法录制通话音频，接通后麦克风可能只返回静音。因此“挂断电话”在**响铃阶段**（拒接）最可靠，通话过程中能否识别取决于机型和 ROM。
- **接听/挂断接口**：`TelecomManager.acceptRingingCall()/endCall()` 在部分 ROM（尤其华为）上不报错也不生效，第三方应用拿不到真正的接听能力。本应用依次尝试 通知按钮 → 无障碍点击/点按/上滑 → 系统接口 → 兼容接口 → 耳机键，日志里会显示实际生效的方式；无障碍没开时，前三种都不会成功。
- **无障碍找不到按钮**：日志会打印 `[无障碍] 界面上没找到… 窗口: type=… 包名:类名 文字[…]`，把这段发出来就能针对该 ROM 的来电界面补规则。
- TTS 只支持 arm64-v8a 真机，模拟器一般跑不起来。

## 构建

```bash
# 需要 Android SDK 34 + JDK 17/21
echo "sdk.dir=/path/to/android-sdk" > local.properties
./gradlew assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

## 结构

| 文件 | 作用 |
| --- | --- |
| `VoiceService.java` | 前台服务：模型下载/解压、Vosk 识别、TTS 播报、来电监听 |
| `VoiceCommands.java` | 口令匹配（配置优先 + 同义词 + 容错） |
| `AppSettings.java` | 口令配置持久化 |
| `PhoneCallHelper.java` | 姓名查询（通讯录/通话记录）、接听、挂断（多级兜底） |
| `CallAccessibilityService.java` | 无障碍点击/点按/上滑接听与挂断，找不到按钮时输出窗口结构 |
| `CallNotificationListener.java` | 来电姓名/号码来源，点击通知上的接听/挂断按钮 |
